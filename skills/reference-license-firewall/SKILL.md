Reference implementations are valuable scientific oracles, but they are not automatically reusable
source material. Keep paper facts, runtime behavior, architecture inspiration, and copied
implementation separate, because they carry different license and provenance obligations.

## Categories

| Category | Meaning | Typical status |
|---|---|---|
| Paper fact | Equation, table, definition, or stated algorithm in the paper | Reusable with citation |
| Runtime oracle | Run the reference code and compare outputs | Usually allowed for validation; cite and document version |
| Black-box value check | Use numerical outputs as regression/parity targets | Usually allowed; do not copy internals |
| Architecture pattern | High-level module boundary or phase decomposition | Usually allowed when independently expressed |
| Line translation | Porting code structure/expression line-by-line | High risk; avoid across incompatible licenses |
| Copied coefficients from code only | Values not present in paper/docs | Treat as code-derived; license and provenance review required |
| Redistribution | Shipping reference code, tables, or generated artifacts | Review license and data terms before including |

## Workflow

1. **Identify the reference**: repo, commit or tag, license, and its role in the work.
2. **Classify each use**: paper source, oracle, black-box target, architecture inspiration, or
   implementation reuse.
3. **Take exact equations and coefficients from verified papers** or permitted data releases, not
   from source lines.
4. **For incompatible licenses, keep a clean room**: one pass may describe behavior and test cases;
   the implementation is derived independently from papers and specs.
5. **Log the boundary**: what was used, what was not, and which files and tests show it.

## Red flags

- "This function is GPL, but I rewrote it in Python" without an independent derivation.
- Coefficients copied from source comments before the paper table was checked.
- Reference-code special cases copied before their physical regime is understood.
- Test fixtures generated by reference code with no version, input, compiler/options, or license note.
