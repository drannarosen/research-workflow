Use right after a change lands (merged or shared) — a renamed symbol, changed signature, altered units/defaults, or new behavior — to actively hunt what the change just made FALSE: docstrings, comments, README/docs claims, cached figures, and example snippets. Gate that the change leaves no confidently-wrong documentation behind it. Don't use for removing the superseded code itself (→ correct-cutover) or recording why the change was made (→ decision-log-and-commits).

A change is done when the code, its tests, and the docs it touched agree. Every rename, signature
change, units or default change, or behavioral shift can falsify the prose around it: a docstring
describing the old return, a comment citing the replaced formula, a README claiming the old behavior,
a committed figure made from old code. Tests don't read prose, so these survive a green suite and
mislead the next reader.

This applies to every change that lands (merged or shared with others). Work on a scratch branch that
won't be merged can defer the sweep; it is owed before the change lands. The width of the sweep scales
with blast radius (a private helper vs. a public API or a units change); a `grep` for the old name or
value across code and docs is the floor. What the sweep finds is fixed, or flagged in the report when
fixing it is out of scope.

## Sweep
- **Docstrings and signatures**: the function's own docstring describes its real arguments, return,
  units, and side effects.
- **Comments near the change**: no comment describes code that no longer exists or a formula you
  replaced.
- **Docs and README**: claims, examples, and quickstarts the new behavior contradicts. Grep the old
  name, flag, or value across the docs, including every place a changed unit or default is asserted
  in words.
- **Figures and outputs**: cached plots, tables, and notebooks generated by the old code are
  regenerated or marked stale (pairs with `run-reproducibility`).
- **Cross-references**: call sites and sibling modules that assumed the old contract.

This is the prose-and-artifact half of finishing a change; removing the superseded code is
`correct-cutover`.

## Related
- `correct-cutover` — removes the old code; this removes the old *claims about* the code.
- `decision-log-and-commits` — records why the change happened; this keeps the surrounding text true to it.
- `run-reproducibility` — figures/outputs falsified by a change must regenerate.
